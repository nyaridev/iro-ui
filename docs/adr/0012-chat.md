# ADR-0012: Chat parts that know nothing of where the words come from

**Status:** Accepted
**Date:** 2026-11-09

## Context

Apps now often talk with an assistant: a conversation of messages, a field to ask in, files attached, the steps the
assistant takes while it works (reasoning, tool calls, a plan), the sources it used, questions it asks back and how
much of its context is used. Kits like AI Elements ship these tied to one SDK's message format. iro-ui has the
pieces they're made of (Prose, CodeBlock, Collapsible, Avatar, TextArea) but not the parts themselves, and every app
would rebuild the same scrolling, streaming and layout rules.

## Decision

- **Presentational parts, no SDK:** `Message`, `Conversation`, `PromptInput`, `Attachment`, `Suggestions`,
  `Reasoning`, `ToolCall`, `Sources` with `Citation`, `Plan`, `Queue`, `Confirmation`, `Questionnaire`, `Shimmer`,
  `Marker` and `UsageMeter`. They take plain props (text, React nodes, arrays of plain objects) and call back;
  an app maps its own message format onto them. Nothing imports an AI library or names a model or vendor.
- **The app renders the words:** a message's content is a React node. Rendered Markdown goes in `Prose` (`sm`),
  code in `CodeBlock`; the chat parts never parse text.
- **Streaming is a flag:** parts that change while an answer streams (`Message`, `Reasoning`) take `streaming`,
  which shows a caret or a shimmer; `ToolCall` and `Plan` steps take a status (running, done, failed).
  `Conversation` stays scrolled to the bottom while the content grows, unless the reader has scrolled up; then a
  "Latest" button brings them back.
- **Roles by layout:** the reader's messages sit at the end on a tinted bubble; the assistant's span the column
  without one, so long answers, code and tables read like a page; system notes are centered and muted.
- **Keys:** `PromptInput` sends on Enter and takes a new line on Shift+Enter; while an answer streams its button
  stops it. `Questionnaire` and `Confirmation` are forms, so they work by keyboard like any other.
- **Built from iro-ui:** the parts reuse Collapsible, Chip, Avatar, TextArea, IconButton and the popup surface; they
  read only tokens and follow the motion modes (ADR-0007). Base UI handles their floating and collapsing parts
  (ADR-0003); the conversation's scroll-follow is hand-built, since Base UI has none.
- **A Chat template** puts them together in the Lab, with a fake answer that streams.

## Options considered

- **Adopt AI Elements or another kit:** complete, but tied to one SDK's types and to shadcn's styling; wrapping it
  to read our tokens would cost more than the parts.
- **One `Chat` component that takes the messages:** less to wire, but every app's message shape differs and the
  layout choices (where suggestions go, when a plan shows) are the app's. Separate parts compose any of them.
- **Markdown parsing inside `Message`:** convenient, but a parser is a dependency and a security decision (HTML in
  answers) that belongs to the app.

## Consequences

- **Easier:** an assistant screen built from iro-ui alone, in every style, with streaming, scrolling and keyboard
  rules done once.
- **Harder:** apps write the small mapping from their message format to the parts.
- **Public surface:** the fifteen parts, their props types and item types.
- **Rules:** `.claude/rules/architecture/components.md` gets a Chat section.
